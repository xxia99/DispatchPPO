# DispatchPPO Reproducibility Code

This archive contains the implementation of DispatchPPO, the learning-based dispatch policy for route-wise decision-dependent anomaly detection described in the paper: *Learning Collision-Free Dispatch Policies for Route-Wise Decision-Dependent Anomaly Detection*.

The training code implements the paper's two-stage method: DispatchNet, the dispatch policy with the collision-free autoregressive decoder (Stage I, trained with PPO), and the executed dispatch policy with the stay bias and the epsilon_IC mixture (Stage II). The archive provides scripts for training, threshold calibration, and testing under the paper's protocol. Model checkpoints and result files are generated by running the commands below.

## 1. Prerequisites

### 1.1 Environment

Use Python 3.10 and a CUDA-capable GPU for normal runs.

```bash
conda create -n uav python=3.10 -y
conda activate uav
pip install -r requirements.txt
```

If the PyTorch build does not match your CUDA driver, install the correct PyTorch build first, then the remaining packages. Run all commands from the repository root. Training keeps SwanLab logging disabled unless `SWMODE=cloud` and a `--swanlab-project` are given.

### 1.2 Dataset

The simulation experiments need no external dataset. Measurements are generated inside the environment (`evaluation/gpu_env.py`): i.i.d. standard normal in control, with a persistent mean shift on the affected locations after the change point.

### 1.3 Generated Checkpoints

Training writes checkpoints under the run directory given to the launcher (`results/<setting>` in the examples). Testing takes the checkpoint path as a command-line argument. No pretrained checkpoint is included in this code-only archive.

## 2. Training

Each of the nine settings of the paper is identified by grid size and fleet size: `g5n1 g5n2 g5n5` (5x5 grid, |B| = 2), `g10n2 g10n5 g10n10` (10x10 grid, |B| = 5), `g30n5 g30n10 g30n30` (30x30 grid, |B| = 10). The 10x10 grid with N = 5 UAVs as the example:

```bash
bash scripts/train_gpu.sh g10n5 results/g10n5
```

The launcher creates the random initialization, writes the full argument list to `results/g10n5/args.txt`, and runs `training/train_dispatch_gpu.py` with the paper's configuration (10,000 PPO updates, 200-step episodes, change point `tau ~ Uniform{5, ..., 50}`, mean shifts {1, 2, 3}). Every 100 updates the policy is validated at the setting's pseudo-threshold (Table 2 of the paper) and `best_XXXX.pt` is saved when the proxy delay improves; `candidate_XXXX.pt` is saved every 20 updates. Environment variables `CU`, `SHIFTS`, `UPDATES`, `SEED`, `DEVICE` and `EXTRA` override the defaults.

## 3. Testing

### 3.1 Test One Checkpoint

```bash
python -m evaluation.evaluate \
  --grid-size 10 --num-uavs 5 --num-anomalies 5 \
  --checkpoint results/g10n5/best_XXXX.pt \
  --label-free --decode-order sorted --epsilon-ic 0.01 \
  --replications 1000 --horizon 2000 --target-arl0 370 --shifts 1,2,3,4 --seed 42 \
  --output results/eval/g10n5.json
```

This calibrates the alarm threshold to `ARL0 = 370` on 1,000 in-control replications, freezes it, and tests ARL1 for `Delta in {1, 2, 3, 4}` on 1,000 out-of-control replications. `--uncertainty-increment` defaults to the paper's `C^U` for the grid size (0.01 on 5x5 and 10x10, 0.001 on 30x30). `--label-free` and `--decode-order` must match the training run.

### 3.2 Test Every Checkpoint of a Run

```bash
python -m evaluation.sweep_checkpoints results/g10n5 \
  --grid-size 10 --num-uavs 5 --num-anomalies 5 \
  --label-free --decode-order sorted --epsilon-ic 0.01 --parallel 4
```

Writes one result file per checkpoint and `SUMMARY.txt` (threshold, ARL0, delays at the four shifts) under `results/g10n5/sweep<seed>`.

## 4. Runtime and GPU Reference

Reference hardware is an NVIDIA A100 40GB GPU; the 30x30 runs also used H200 GPUs. Peak GPU memory of training with the default batch sizes (512 environments on 5x5 and 10x10, 256 on 30x30):

| Setting | Peak GPU memory | Time per PPO update |
|---|---:|---:|
| g5n1 | 0.7 GB | 2.5 s |
| g5n5 | 1.4 GB | 6 s |
| g10n2 | 1.5 GB | 4 s |
| g10n5 | 1.9 GB | 5-10 s |
| g10n10 | 3.1 GB | 13 s |
| g30n5 | 5.8 GB | 8 s |
| g30n10 | 5.8 GB | 13 s |
| g30n30 | 6.7 GB | 28 s |

A 10,000-update run takes from under a day (5x5) to about two to three days (10x10 with N = 10, 30x30). Testing one checkpoint takes a few minutes and under 1 GB; reduce `--chunk-size` on a smaller GPU. `--device cpu` works for small smoke tests.
